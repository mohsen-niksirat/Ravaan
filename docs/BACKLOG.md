## ۱. معماری کلی سیستم (Architecture Summary)

پروژه **Ravaan (روان)** یک دستیار هوشمند و بومی تایپ برای کاربران دوزبانه (فارسی/انگلیسی) در محیط سیستم‌عامل ویندوز (Windows 10 و 11) است که با پایتون و وابستگی‌های سبک و حداقلی طراحی شده است:

```
┌──────────────────────────────────────────────────────────────┐
│                       UI & Presentation                      │
│   (Tkinter + Pystray: Overlay, Tray, Settings, Toast, Dialogs)│
└──────────────────────────────▲───────────────────────────────┘
                               │ Thread-safe Queue / Polling
┌──────────────────────────────┴───────────────────────────────┐
│                      Ravaan Core Engine                      │
│   - Predictor & N-Gram Model      - AutoFix (Layout Detection)│
│   - ZWNJ & Normalizer             - Snippets 3.0 & Macros     │
│   - Transliteration (Finglish)    - Learning Engine & Decay   │
│   - Calc, Num2Words & Jalali      - DPAPI Crypto & Sync       │
└──────────────────────────────▲───────────────────────────────┘
                               │
┌──────────────────────────────┴───────────────────────────────┐
│                    Windows Platform Layer                    │
│   - WinAPI ctypes bindings        - Caret Tracking (UIA/GUI)  │
│   - WH_KEYBOARD_LL Hook Thread    - Layout Switching (HKL)    │
│   - SendInput Event Injection     - Elevation & Focus Monitor │
│   - Mutex SingleInstance          - CF_DIB / Unicode Clipboard│
└──────────────────────────────────────────────────────────────┘
```

## ۲. ارزیابی ریسک‌های سیستمی (Risky Code Inventory)

### ۱. هوک سراسری کیبورد (`WH_KEYBOARD_LL` در `ravan/platform/hook.py`)
- **ریسک:** ویندوز دارای مکانیزم ایمنی `LowLevelHooksTimeout` (معمولاً ۲۰۰ میلی‌ثانیه) است. اگر ترد هوک مسدود شود یا پاسخی با تأخیر ارسال کند، ویندوز هوک را بدون اطلاع قبلی از زنجیره حذف (Unhook) می‌کند.
- **وضعیت فعلی:** عملیات بافر در یک ترد مجزا با `queue.Queue(maxsize=1024)` ایزوله شده است.
- **اقدام لازم در فاز ۵:** افزودن مکانیزم ناظر (Watchdog / Auto-Recovery) برای بازیابی خودکار هوک در صورت بسته شدن ناگهانی توسط ویندوز، بازگشت از Sleep/Resume، قفل صفحه (Lock Screen) یا اتصال RDP.

### ۲. تزریق کاراکترها با `SendInput` (`ravan/platform/inject.py`)
- **ریسک:** در تایپ سریع کاربر، اگر کلیدهای جدید در حین ارسال Backspace یا تزریق نویسه‌های یونیکد فشرده شوند، امکان تداخل و جابجایی ترتیب کلیدها وجود دارد.
- **وضعیت فعلی:** رویدادهای تزریقی با فلگ `LLKHF_INJECTED` نشانه‌گذاری می‌شوند تا هوک آن‌ها را بازخوانی نکند.
- **اقدام لازم در فاز ۱ و ۲:** استفاده از تراکنش‌های اتمیک در تزریق و تست استقامت (Stress Test) زیر بار تایپ پرسرعت.

### ۳. عملیات کلیپ‌بورد (`ravan/platform/clipboard.py`)
- **ریسک:** تابع `OpenClipboard` در صورتی که توسط برنامه دیگری (مانند نرم‌افزارهای مدیریت کلیپ‌بورد) در همان میلی‌ثانیه باز باشد، با خطا مواجه می‌شود.
- **وضعیت فعلی:** پیاده‌سازی حلقه تلاش مجدد با وقفه تصاعدی (Exponential Backoff با ۵ تکرار).

### ۴. همزمانی ترد رابط کاربری و هوک کیبورد (Threading & Tkinter)
- **ریسک:** فریم‌ورک Tkinter قابلیت Thread-safe ندارد و هرگونه دسترسی به عناصر گرافیکی از تردهای پس‌زمینه می‌تواند باعث Fatal Crash شود.
- **وضعیت فعلی:** رویدادهای کیبورد صرفاً درون صف قرار می‌گیرند و ترد اصلی GUI از طریق حلقه `root.after()` صف را پیمایش می‌کند.
